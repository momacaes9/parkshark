🦈 ParkShark Duke · Privacy

Hackathon prototype (Triangle AI Hackathon, Robotics track). Last updated November 2026.

In one sentence: ParkShark counts cars, not people. Plates are turned into a salted hash on the sensor itself, the camera image is deleted right after reading, and nothing can identify you or track where you drive.

What we do not collect

  • No images are kept. The plate photo exists only in the Pi's memory long enough to run OCR (about a second) and is then deleted. Images never go over LoRa or to the cloud.
  • No raw plate numbers leave the Pi, and they are never written to disk or to the database.
  • No names, DukeCard data, permit records or anything linking a vehicle to a person.
  • No location tracking of drivers. The website never asks for your GPS location. The "start point" on the map is a pin you place yourself, and it stays in your browser.
  • No accounts, cookies, ads or analytics.
  • No payment data. The Reserve / Pay button is a demo using Google Pay's TEST environment with the example gateway. It returns a dummy token that is thrown away, and nothing is charged.

How the hash protects you

Each sensing session uses a fresh random salt that is kept only in the Pi's memory. The database stores sha256(salt ‖ plate). Without the salt, nobody (including us) can reverse the hash or check whether a given plate was seen. When the session ends the salt is destroyed, and the hashes from that session can never be linked to any other session.

During the hackathon the live plate demo runs only on team members' and volunteers' cars, with their consent. If plate reading fails, the fallback ID is arrival order plus timestamp, which contains no plate at all.

Who can see what

  • The public dashboard can read only anonymous occupancy (Supabase Row Level Security, read-only for the public key).
  • The vehicle_events table (hashes) has RLS enabled and no public policy. Only the sensor gateway's server key can write it.

Third-party services the website calls

  • Esri (satellite and street tiles) and unpkg (Leaflet library): standard web requests for map tiles and code.
  • Open-Meteo (weather): asked for the weather at Wilkinson Building's coordinates, not yours.
  • Google Pay (only if you open the demo checkout), in TEST mode.
  • Google Gemini (only if you use the Parking Concierge): your chat messages and the parking data the concierge looks up are sent through our server to Google's Gemini API to write the answer. Your location is never included, and we do not store the conversation.
  • Lots you draw with the "Draw lot" tool are saved only in your browser (localStorage) until you download them.

Open data

Parking inventory is © OpenStreetMap contributors (ODbL). Curb verification uses NC OneMap orthoimagery (NC CGIA), where vehicles show up as anonymous shapes at 15 cm per pixel. No Google-derived data is used for the inventory.
